## Detailed Findings by Severity

### P1 Major

**[P1] No visible focus indicators on interactive elements**
- **Location:** `style.css` (global), `remove.html` (inline input styles)
- **Category:** Accessibility
- **Impact:** Keyboard users and screen reader users cannot see which element is focused. Filter buttons, links, and form inputs have no visible focus ring. WCAG 2.4.7 (Focus Visible) requires it.
- **WCAG:** 2.4.7 Focus Visible (Level AA)
- **Recommendation:** Add a `:focus-visible` ring to all interactive elements. Use the accent color or a subtle white outline.
  ```css
  *:focus-visible {
    outline: 2px solid var(--accent);
    outline-offset: 2px;
  }
  ```
- **Suggested command:** `$impeccable polish style.css`

**[P1] Inline styles on remove.html and about.html bypass the token system**
- **Location:** `remove.html` (lines 17–61), `about.html` (lines 17–64)
- **Category:** Theming
- **Impact:** ~90% of the styling on these pages is inline, which means:
  - No CSS variables, so dark mode changes require editing every element
  - No `:focus` or `:hover` pseudo-classes possible on inline styles (already causing the focus issue)
  - If you change a token, these pages won't update
  - Impossible to maintain a consistent design system
- **Recommendation:** Extract all inline styles to CSS classes in `style.css`. Use the existing token variables. This is the single biggest maintenance debt on the site.
- **Suggested command:** `$impeccable polish remove.html`

### P2 Minor

**[P2] No tablet breakpoint — 3-col grid snaps to 1-col at 480px**
- **Location:** `style.css` line 108 (grid definition), line 254 (media query)
- **Category:** Responsive Design
- **Impact:** At tablet widths (768–1024px), the grid shows 3 columns which are too wide for comfortable reading on iPad. It stays at 3 columns until 480px where it snaps to 1 column. Missing 2-column tablet range.
- **Recommendation:** Add a tablet breakpoint at ~768px that sets `grid-template-columns: repeat(2, 1fr)`.
  ```css
  @media (max-width: 768px) and (min-width: 481px) {
    .entries-grid { grid-template-columns: repeat(2, 1fr); }
  }
  ```
- **Suggested command:** `$impeccable adapt style.css`

**[P2] Form inputs on remove.html have no `:focus` or `:focus-visible` styles**
- **Location:** `remove.html` inline styles
- **Category:** Accessibility
- **Impact:** Form fields have no visual change on focus. Users don't know which field they're editing. WCAG 2.4.7 violation.
- **WCAG:** 2.4.7 Focus Visible
- **Recommendation:** Add `:focus` border color shift to the accent. Requires moving styles to CSS (see P1 above).
  ```css
  input:focus {
    border-color: var(--accent);
    outline: none;
  }
  ```
- **Suggested command:** `$impeccable polish remove.html`

**[P2] "No doxxing. No private data." repeated across the site**
- **Location:** `index.html` (footer), `about.html` (footer), `about.html` (body)
- **Category:** Anti-Pattern (aphoristic cadence)
- **Impact:** The phrase appears in 3+ locations. Once is voice; three times is filler. Tighten to one location.
- **Recommendation:** Keep it on `about.html` body copy. Remove from `index.html` footer and `about.html` footer. The index footer has limited space — use it for something more actionable.
- **Suggested command:** `$impeccable clarify index.html`

**[P2] No `prefers-reduced-motion` media query**
- **Location:** `style.css` lines 275–282 (fadeIn animation)
- **Category:** Accessibility
- **Impact:** The card fade-in animation runs for everyone, including users who explicitly requested reduced motion. WCAG 2.3.3 (Motion) recommends respecting the preference.
- **WCAG:** 2.3.3 Sensory Characteristics (Level A)
- **Recommendation:** Wrap the animation in a `prefers-reduced-motion` check:
  ```css
  @media (prefers-reduced-motion: no-preference) {
    .entry-card { animation: fadeIn 0.3s ease-out; }
  }
  ```
- **Suggested command:** `$impeccable polish style.css`

### P3 Polish

**[P3] Formspree endpoint is `REPLACE_ME` — will fail silently**
- **Location:** `remove.html` line 98
- **Category:** Performance (broken API call)
- **Impact:** The form tries to POST to `https://formspree.io/f/REPLACE_ME`, which returns 404 and falls back to mailto. The "Sending..." state appears briefly before the fallback fires, which looks like a bug to the user.
- **Recommendation:** Either register a Formspree endpoint or remove the Formspree attempt entirely and go straight to mailto fallback.
- **Suggested command:** `$impeccable harden remove.html`

**[P3] No `prefers-color-scheme` support**
- **Location:** `style.css` `:root`
- **Category:** Theming
- **Impact:** The site is dark-only. No light mode exists and no light mode is requested. This is fine for this brand — a forensic dark-only aesthetic is a valid choice. Noting only for awareness.
- **Recommendation:** None. Skip this. Dark-only is intentional.
- **Suggested command:** N/A

**[P3] Status tag colors are hardcoded in CSS, not in DESIGN.md sidecar**
- **Location:** `style.css` lines 154–157
- **Category:** Theming
- **Impact:** The status colors (`#451a03`, `#1e1b4b`, `#14532d`, `#064e3b`) are defined in DESIGN.md but the CSS uses literal hex values. If DESIGN.md changes, CSS won't update.
- **Recommendation:** Already using CSS variables in DESIGN.md definition. Consider converting to CSS custom properties: `--status-active-bg: #451a03`.
- **Suggested command:** `$impeccable document style.css`

## Patterns & Systemic Issues

1. **Inline style sprawl on content pages.** `remove.html` and `about.html` are 90% inline styles. This is the single biggest technical debt on the site — it blocks focus styles, theming updates, and responsive tweaks. Extract to CSS classes once and it cascades into fixing multiple P1/P2 issues.

2. **Accessibility gap is consistent, not sporadic.** No focus indicators, no `prefers-reduced-motion`, no `aria-label` on filter buttons. The site works for sighted mouse users perfectly — it's the keyboard and assistive-technology path that's bare. This is a pattern, not a mistake.

---

## Positive Findings

1. **Zero external dependencies.** No frameworks, no build tools, no Node packages. The site is 4 HTML files, 1 CSS file, 1 JS file, and 12 JSON entries. Total bundle: ~23KB. This is exactly how a static site should be.

2. **Performance is excellent.** No layout thrashing, no expensive animations (fadeIn uses opacity + transform only), no images to lazy-load, no JavaScript frameworks to hydrate. The site will load instantly on any connection.

3. **Anti-pattern score is clean.** The detector found zero actual anti-patterns — only warnings about intentional brand choices (monospace-only) and minor formatting (aphoristic repetition). The site is genuinely distinctive.

4. **Filter URL persistence works correctly.** The `?tool=cursor` pattern is clean, shareable, and respects the back button. Good implementation.

5. **The graveyard metaphor is executed with discipline.** Monospace authority, flat surfaces, one accent color, generous spacing. The design system holds together.
