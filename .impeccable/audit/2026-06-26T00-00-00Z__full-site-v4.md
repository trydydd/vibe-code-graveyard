## Detailed Findings

### [P2] Filter button touch targets below 44px

- **Location**: `style.css` — `.filter-btn`
- **Category**: Responsive / Accessibility
- **Impact**: `.filter-btn` with `padding: 0.75rem 1rem` and `font-size: 0.85rem` produces ~40px hit height. WCAG 2.5.5 requires 44×44px for interactive controls. On mobile the buttons are even smaller (0.75rem padding, 0.8rem font = ~39px). In a horizontal-scroll filter bar, fingers miss the target more often.
- **WCAG**: 2.5.5 Target Size (Minimum) — Level AA
- **Recommendation**: Add `min-height: 44px` to `.filter-btn`. This is a one-line fix.
- **Suggested command**: `/impeccable adapt`

### [P3] White on --accent (#e13021) is 4.52:1 — passes but borderline

- **Location**: `style.css` — `.btn`, `.filter-btn.active`, `.skip-link`
- **Category**: Accessibility
- **Impact**: 4.52:1 technically passes WCAG AA (threshold 4.5:1) but leaves essentially no margin. A monitor calibrated slightly differently or a user with mild color deficiency may perceive lower contrast. The value is correct per spec but fragile.
- **WCAG**: 1.4.3 Contrast Minimum — Level AA (passes; noted for awareness)
- **Recommendation**: Bump `--accent` to `#d62b1a` (L slightly lower, increasing contrast to ~4.8:1 while keeping Morgue Red character), or accept current value since it technically passes.
- **Suggested command**: `/impeccable colorize` (if bump is wanted)

### [P3] Repeated "Source ↗" link text across entry cards

- **Location**: `script.js` line ~118 — entry card template
- **Category**: Accessibility
- **Impact**: Every card renders `<a>Source ↗</a>`. Screen readers reading links out of context (common navigation pattern) hear a list of identically-named links with no differentiation. WCAG 2.4.4 allows context-based link purpose (surrounding article element satisfies the letter of the spec), but in practice this degrades keyboard navigation.
- **WCAG**: 2.4.4 Link Purpose (In Context) — Level AA (passes contextually); 2.4.9 Link Purpose (Link Only) — Level AAA (fails)
- **Recommendation**: Add `aria-label` to each source link: `aria-label="Source for ${name} ↗"`. One-line change in the card template.
- **Suggested command**: `/impeccable harden`

## Positive Findings

1. **Contrast is fully solved.** The two-token accent split (`--accent` for surfaces, `--accent-text: #f04832` for text) is working correctly. All text/background pairs verified at ≥4.5:1.

2. **Animation is compositor-safe.** `fadeIn` uses only `opacity` and `transform`. Reduced-motion is guarded via `@media (prefers-reduced-motion: no-preference)` wrapper, so animation never fires when the user has motion sensitivity. The timing at `i * 0.04s` stagger is tight and purposeful.

3. **Token system is watertight.** Zero hard-coded color values anywhere in `style.css`. All theme values flow from `:root` custom properties. Status colors are tokenized separately from accent.

4. **Security posture is correct.** `escapeHtml()` applied to all entry fields before innerHTML; `safeUrl()` rejects non-http(s) sources; querySelector injection from URL params is try-caught.

5. **Skip link works properly.** `position: fixed; top: -100%` slides to `top: 0` on focus — no layout shift, no z-index conflict (9999 is justified here as skip links must clear everything).

6. **Em dash sweep is complete.** No em dashes remain in any site file, documentation file, or rendered entry data (including `_entries.json`).
